# D1 · Trackium Lite production readiness audit

**Audit date:** 25 November 2026 (Kyiv). **Baseline:** `d001c66381a9ef88f4e8fafb6ec46d4d99a7a940`, the merged C3 [PR #98](https://github.com/themightydanik/trackium/pull/98). Scope covers Fleet Map V2, B2/B3, the private Valhalla adapter and the Lite APK. The audit reviewed repository and CI evidence and ran local checks. Live production controls, credentials, databases and topology were outside the inspection boundary.

## Recommendation

| Stage | Decision | Release boundary |
| --- | --- | --- |
| Code merge | **GO** for repository-only changes | C3's implementation is merged and tested. This audit is documentation only. If merging a branch triggers a live source deploy, use the deployment decision instead. |
| Isolated staging | **CONDITIONAL GO** | Operator approval, a private test deployment with the pinned graph and a disposable staging tenant, an environment-specific HTTPS origin, safe defaults and smoke verification are prerequisites. Physical APK staging needs its own trusted-origin solution. |
| Controlled production pilot | **NO-GO** | Private network, feature exposure, migration/restore, observability, capacity, pilot geography and physical device evidence are still open. |
| General production | **NO-GO** | In addition to the pilot gates, there is no accepted generally available coverage, production-scale soak or recovery evidence. |

Severity describes the consequence if a finding is unresolved at release. A local or CI **PASS** is limited to the named scope. **FAIL** identifies a specific missing requirement or measured mismatch. **NOT VERIFIED** means the evidence is insufficient for that scope. **NOT APPLICABLE** means the operation is intentionally outside D1. See the [operational acceptance matrix](PRODUCTION_ACCEPTANCE_MATRIX.md) for owners, minimum evidence, rehearsal and rollback.

The attestor exposes only route and status, and the engine listens on container loopback. C3 CI executes the real Gateway/browser flow and separately checks the private topology. The B2 resolver pins an RFC1918/loopback IPv4 result, even for a `.railway.internal` hostname. An IPv6-only target cannot work with the present adapter. Private HTTP and attestation headers rely on trusted network peers. The actual target DNS, routes, ingress, deployment triggers and access controls remain unverified. ## Capacity risk to test before pilot

A full Lite page can request 154 base reads per refresh with 25 shipments and 25 devices, plus up to two optional notifications/Integritas requests. The count is derived from the code: session, lists and simulations (4), shipment detail/events/proofs (75), device status/location/history (75). Two selected-route reads can occur every 15 seconds on the existing scheduler. A poll waits three seconds after the prior refresh completes. A theoretical three-second cycle at 154 calls produces about 3,080 requests/minute per browser. Actual throughput depends on workload and response time. The repository's Railway **test** ingress cap is 1,200 requests/minute and 32 in flight per process; a saturated full-page browser may hit this cap, especially with other users. The cap is not evidence of the actual production edge policy. Load-test the intended profile without weakening the guard to make the test pass. Gateway's ordinary connection pool has a 10-connection limit per process. [Browser fan-out](../assets/v2/server-client.js#L114) · [Ingress guard](../services/gateway/src/ingress.js#L33) · [Pool](../services/gateway/src/journal.js)

## Reproducibility

All commands below are for a local checkout, with the repository's dependencies and pinned Android SDK already installed. The Valhalla procedure uses existing checksum-reviewed graph files and starts a disposable Valhalla service only. The standalone probe uses the engine directly; previous B2/C3 workflows provide authenticated Gateway/B3 evidence. Do not use these commands against a production database or Compose project.

```sh
git rev-parse HEAD
npm --prefix services/gateway test
npm --prefix .railway run check
npm --prefix .railway test
NODE_PATH=/path/to/ui-tools/node_modules node --test --test-concurrency=1 \
  tests/minidapp/fleet-map.test.cjs tests/minidapp/road-basemap.test.cjs \
  tests/minidapp/route-planner.test.cjs tests/minidapp/route-lifecycle.test.cjs
apps/android/gradlew -p apps/lite-android --offline --no-daemon \
  :app:testDebugUnitTest :app:assembleDebug --rerun-tasks

export COMPOSE_PROJECT_NAME=trackium-d1-ukraine
export VALHALLA_GRAPH_DIR=/path/to/reviewed/graph-ukraine
docker compose -f routing/valhalla/compose.yaml up -d --wait --wait-timeout 120
docker compose -f routing/valhalla/compose.yaml exec -T valhalla \
  python3 - ukraine < routing/valhalla/probe.py
docker inspect "${COMPOSE_PROJECT_NAME}-valhalla-1" \
  --format '{{.HostConfig.NanoCpus}} {{.HostConfig.Memory}} {{.HostConfig.PidsLimit}} {{json .HostConfig.PortBindings}}'
docker compose -f routing/valhalla/compose.yaml exec -T valhalla \
  cat /sys/fs/cgroup/cpu.max /sys/fs/cgroup/memory.max /sys/fs/cgroup/pids.max
docker compose -f routing/valhalla/compose.yaml stop valhalla
```

Repeat with graph `graph-arterial` and mode `corridors`, or the separate synthetic graph and mode `fixture`, using distinct project names. Rebuild from [approved inputs and manifest procedure](valhalla-b1/README.md) if local graphs are unavailable. Archived C3 checks were green on PR head, and the post-merge MiniDapp workflow passed on the audit commit. [Post-merge Chromium evidence](https://github.com/themightydanik/trackium/actions/runs/45672794730)
